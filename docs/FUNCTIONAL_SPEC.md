# SimControl 기능명세

## 1. 제품 목표

SimControl은 현재 시스템에서 선택된 Xcode를 기준으로 설치된 시뮬레이터 런타임과 생성된 시뮬레이터 디바이스를 조회하고 조작하는 macOS 앱이다.

초기 버전은 런타임 설치 도구나 Xcode 빌드 도구가 아니라, Active Xcode의 `simctl`이 제공하는 시뮬레이터 상태를 읽고 디바이스 중심 작업을 실행하는 관리 콘솔을 목표로 한다.

## 2. MVP 범위

### 2.1 지원 플랫폼

- iOS, watchOS, tvOS, visionOS를 1급 지원 플랫폼으로 취급한다.
- `simctl`이 제공하는 알 수 없는 플랫폼이나 새 플랫폼은 목록에 표시하되 Unknown 또는 Other로 분류한다.
- Unknown 또는 Other 플랫폼은 조회와 삭제 같은 보수적인 작업만 허용한다.

### 2.2 포함 기능

- Active Xcode 기준 환경 진단
- 시뮬레이터 디바이스 인벤토리 조회
- 설치된 시뮬레이터 런타임 카탈로그 조회
- 시뮬레이터 디바이스 생성
- 시뮬레이터 디바이스 부팅, 종료, Simulator.app에서 열기
- 시뮬레이터 디바이스 초기화와 삭제
- 여러 디바이스 대상 일괄 종료, 초기화, 삭제
- 빌드 완료된 `.app` 번들 설치
- 단일 디바이스에서 Target App 실행
- watchOS 등 companion 관계가 있는 디바이스의 페어링 상태 표시
- 작업 결과와 `simctl` 제공 정보 표시

## 3. 주요 화면

초기 버전은 단일 윈도우로 구성한다.

- 상단 툴바: 새 디바이스, 새로고침, 일괄 작업, 현재 Active Xcode 경로
- 좌측 사이드바: 플랫폼, 런타임 버전, 상태 필터
- 중앙 영역: 디바이스 중심 인벤토리 테이블
- 우측 상세 패널: 선택된 디바이스의 상세 정보, 작업 버튼, 페어링 정보, Target App 설치/실행 영역
- 환경 문제 상태: `xcrun simctl`을 사용할 수 없을 때 Device Inventory 대신 표시하는 진단 화면

## 4. Active Xcode와 환경 진단

- 앱은 `xcode-select`로 선택된 Active Xcode 하나만 기준으로 동작한다.
- 사용자는 현재 기준 Xcode 경로를 확인할 수 있어야 한다.
- 앱 시작 시 Active Xcode 경로와 `xcrun simctl` 사용 가능 여부를 확인한다.
- Xcode가 설치되어 있지 않거나, Command Line Tools만 선택되어 있거나, `xcode-select`가 Xcode가 아닌 경로를 가리키거나, Xcode 라이선스 미동의 등으로 `simctl`을 사용할 수 없으면 환경 문제 상태를 표시한다.
- 환경 문제 상태에서는 문제 설명과 `xcrun` 또는 `simctl`이 제공한 정보를 표시한다.
- 사용자가 앱 밖에서 환경 문제를 해결한 뒤 수동 새로고침할 수 있어야 한다.

## 5. 디바이스 인벤토리

초기 화면의 중심은 런타임이 아니라 생성된 시뮬레이터 디바이스 목록이다.

### 5.1 표시 정보

- 디바이스 이름
- UDID
- 플랫폼
- 런타임 버전
- 디바이스 타입
- 상태
- availability 문제
- 페어링 관계 및 경고

### 5.2 상태 갱신

- 사용자는 새로고침 버튼으로 디바이스 인벤토리를 즉시 갱신할 수 있다.
- 디바이스 생성, 부팅, 종료, 초기화, 삭제, Target App 설치, Target App 실행 작업이 끝나면 디바이스 인벤토리를 자동으로 갱신한다.
- 앱이 active 상태로 전환되면 디바이스 인벤토리를 자동으로 갱신한다.

## 6. 런타임 카탈로그

- 앱은 Active Xcode에 설치된 런타임을 읽기 전용 카탈로그로 보여준다.
- 각 런타임은 플랫폼, 버전, build version, identifier, availability 상태를 표시한다.
- 각 런타임은 해당 런타임으로 생성된 디바이스 수를 표시한다.
- 사용자는 런타임을 기준으로 디바이스 인벤토리를 필터링할 수 있다.
- 사용자는 선택한 런타임에서 새 디바이스 생성 플로우로 진입할 수 있다.

## 7. 디바이스 생성

- 사용자는 플랫폼, 런타임 버전, 디바이스 타입, 디바이스 이름을 선택하거나 입력한다.
- 디바이스 타입은 생성 플로우 안에서만 선택지로 제공한다.
- 선택한 플랫폼과 런타임에 호환되지 않는 디바이스 타입은 숨기거나 비활성화한다.
- Unknown 또는 Other 플랫폼에는 새 디바이스 생성 UX를 제공하지 않는다.
- 디바이스 이름은 디바이스 타입과 런타임을 바탕으로 자동 제안한다.
- 제안된 이름이 이미 존재하면 자동으로 번호를 붙인다.
- UDID가 디바이스의 고유 식별자이며 이름은 식별자로 사용하지 않는다.

## 8. 디바이스 작업

### 8.1 작업 실행 모델

- 작업은 가능한 한 디바이스 단위로 잠근다.
- 작업 중인 디바이스는 관련 작업 버튼을 비활성화한다.
- 다른 디바이스에는 독립적인 작업을 실행할 수 있다.
- 전체 새로고침 중에도 목록은 읽을 수 있어야 한다.
- 전체 새로고침 중 충돌 가능성이 큰 작업 버튼은 일시적으로 비활성화할 수 있다.
- 일괄 작업은 대상 디바이스별 진행 상태를 표시한다.
- 일괄 작업 결과는 성공 항목과 실패 항목을 분리해 보여준다.
- Unavailable 상태의 디바이스는 삭제 외 작업을 비활성화한다.
- Unavailable 상태의 디바이스는 일괄 삭제에 포함할 수 있지만, 다른 일괄 작업에서는 제외한다.

### 8.2 일반 작업

- Boot는 디바이스를 사용 가능한 상태로 만드는 작업이다.
- Shutdown은 디바이스를 종료하는 작업이다.
- Open in Simulator는 Simulator.app에서 해당 디바이스 UI를 표시하는 작업이다.
- Boot 작업은 기본적으로 Simulator.app 창 표시를 요구하지 않는다.
- 이미 Booted 상태인 디바이스도 Open in Simulator 작업을 실행할 수 있다.
- 여러 디바이스를 대상으로 일괄 종료할 수 있다.

### 8.3 파괴적 작업

다음 작업은 실행 전에 확인을 요구한다.

- 디바이스 데이터 초기화
- 디바이스 삭제
- 여러 디바이스 일괄 초기화
- 여러 디바이스 일괄 삭제

Booted 상태의 디바이스를 삭제할 때는 앱이 종료 후 삭제를 수행할 수 있지만, 실행 전에 사용자가 이를 확인해야 한다.

## 9. Target App 설치 및 실행

- 사용자는 빌드 완료된 `.app` 번들을 선택하거나 드래그 앤 드롭으로 제공한다.
- 앱은 선택한 단일 디바이스에 `.app` 번들을 설치할 수 있다.
- 앱은 선택한 여러 디바이스에 `.app` 번들을 일괄 설치할 수 있다.
- 앱은 선택한 단일 디바이스에서 설치된 Target App의 bundle identifier를 확인하고 실행한다.
- Target App 설치와 실행은 Booted 상태의 디바이스에서만 가능하다.
- 선택한 디바이스가 Booted 상태가 아니면 Target App 설치와 실행 동작을 비활성화한다.
- Target App 설치와 실행은 디바이스를 자동으로 부팅하지 않는다.

## 10. 페어링 표시

- Device Pairing은 iPhone과 Apple Watch simulator처럼 companion 관계가 있는 시뮬레이터 디바이스 사이의 관계다.
- 초기 버전은 기존 Device Pairing 관계와 경고를 표시한다.
- Device Pairing은 디바이스 상세 패널과 인벤토리 경고 정보에서 확인할 수 있어야 한다.

## 11. 오류 및 결과 표시

- 디바이스 작업, 런타임 조회, Target App 설치/실행 실패 시 `simctl`이 제공한 정보를 표시한다.
- 앱은 실패한 작업 이름, 대상 디바이스 이름, 대상 UDID를 함께 표시한다.
- 일괄 작업은 항목별 성공/실패 결과를 표시한다.
- `simctl` 출력은 사용자가 복사할 수 있어야 한다.

## 12. 설정, 저장, 앱 생명주기

- 초기 버전에서는 별도 Preferences 화면을 제공하지 않는다.
- 현재 Active Xcode 경로는 메인 화면 상단 또는 환경 진단 영역에 표시한다.
- 파괴적 작업 확인은 항상 요구하며, 이를 끄는 설정은 제공하지 않는다.
- 초기 버전은 창 크기와 분할 위치만 영구 저장한다.
- 시뮬레이터 디바이스 목록과 런타임 목록은 영구 저장하지 않는다.
- 마지막 선택 필터, 마지막 선택 디바이스, 마지막 선택 `.app` 번들 경로는 영구 저장하지 않는다.
- `simctl` 결과 이력과 로그는 영구 저장하지 않는다.
- 실제 시뮬레이터 상태의 출처는 Active Xcode와 `simctl` 출력이다.

## 13. 시뮬레이터 백엔드

- 초기 버전의 시뮬레이터 조회와 작업 실행은 Active Xcode의 `xcrun simctl`을 사용한다.
- 인벤토리 조회는 `xcrun simctl list --json` 계열 출력을 기준으로 한다.
- 디바이스 작업은 `xcrun simctl boot`, `shutdown`, `erase`, `delete`, `create`, `install`, `launch` 계열 명령을 사용한다.
- 초기 버전에서는 CoreSimulator private framework에 직접 연동하지 않는다.
- 초기 버전에서는 Xcode 또는 CoreSimulator 내부 데이터베이스를 직접 파싱하지 않는다.
- 이 결정은 [ADR-0001](./adr/0001-use-simctl-as-simulator-backend.md)에 기록한다.

## 14. 사용자 시나리오

### 14.1 환경 확인

사용자는 앱을 열고 현재 Active Xcode가 무엇인지 확인한다. `simctl`을 사용할 수 없는 환경이면 사용자는 디바이스 목록 대신 환경 문제와 `xcrun` 또는 `simctl`이 제공한 정보를 본다.

### 14.2 디바이스 탐색

사용자는 생성된 시뮬레이터 디바이스를 플랫폼, 런타임 버전, 상태로 필터링하고, 선택한 디바이스의 UDID, 런타임, 상태, availability 문제, 페어링 정보를 확인한다.

### 14.3 디바이스 생성

사용자는 지원 플랫폼과 설치된 런타임을 선택하고, 호환되는 디바이스 타입을 골라 새 시뮬레이터 디바이스를 만든다. 앱은 디바이스 이름을 제안하고, 이름 충돌이 있으면 자동으로 번호를 붙인다.

### 14.4 디바이스 조작

사용자는 선택한 디바이스를 부팅, 종료, Simulator.app에서 열기, 초기화, 삭제할 수 있다. 삭제와 초기화는 실행 전에 확인을 요구하며, booted 디바이스 삭제는 종료 후 삭제를 수행한다는 확인을 요구한다.

### 14.5 Target App 설치와 실행

사용자는 빌드 완료된 `.app` 번들을 Booted 상태의 디바이스에 설치하고, 단일 디바이스에서 실행한다. 여러 Booted 디바이스에는 `.app` 번들을 일괄 설치할 수 있지만, 일괄 실행은 제공하지 않는다.

## 15. Acceptance Criteria

### 15.1 환경 진단

- Given `xcrun simctl`을 사용할 수 있는 환경, When 앱을 실행하면, Then Active Xcode 경로와 디바이스 인벤토리를 표시한다.
- Given `xcrun simctl`을 사용할 수 없는 환경, When 앱을 실행하면, Then 디바이스 인벤토리 대신 환경 문제 상태와 `xcrun` 또는 `simctl` 제공 정보를 표시한다.
- Given 환경 문제 상태, When 사용자가 앱 밖에서 문제를 해결하고 새로고침하면, Then 앱은 환경을 다시 진단하고 사용 가능한 경우 디바이스 인벤토리를 표시한다.

### 15.2 디바이스 인벤토리

- Given `simctl`이 디바이스 목록을 제공하면, When 인벤토리를 표시할 때, Then 각 디바이스의 이름, UDID, 플랫폼, 런타임 버전, 디바이스 타입, 상태, availability 문제를 표시한다.
- Given 사용자가 플랫폼, 런타임 버전, 상태 필터를 선택하면, When 필터가 적용될 때, Then 중앙 인벤토리 테이블은 조건에 맞는 디바이스만 표시한다.
- Given 앱이 active 상태로 전환되거나 디바이스 작업이 완료되면, When 갱신이 실행될 때, Then 최신 `simctl` 출력 기준으로 인벤토리를 다시 표시한다.

### 15.3 런타임 카탈로그

- Given 설치된 런타임이 있으면, When 런타임 카탈로그를 표시할 때, Then 플랫폼, 버전, build version, identifier, availability 상태, 생성된 디바이스 수를 표시한다.
- Given 사용자가 런타임을 선택하면, When 필터를 적용할 때, Then 해당 런타임의 디바이스만 인벤토리에 표시한다.
- Given 사용자가 런타임에서 새 디바이스 생성을 시작하면, When 생성 플로우가 열릴 때, Then 선택한 런타임이 생성 입력에 반영된다.

### 15.4 디바이스 생성

- Given 사용자가 지원 플랫폼과 설치된 런타임을 선택하면, When 디바이스 타입을 선택할 때, Then 호환되는 디바이스 타입만 선택 가능하다.
- Given 제안된 디바이스 이름이 이미 존재하면, When 디바이스 생성 플로우를 표시할 때, Then 앱은 자동으로 번호가 붙은 이름을 제안한다.
- Given 새 디바이스 생성이 성공하면, When 작업이 완료될 때, Then 앱은 인벤토리를 자동 갱신하고 새 디바이스를 표시한다.
- Given 새 디바이스 생성이 실패하면, When 결과를 표시할 때, Then 실패한 작업 이름과 `simctl` 제공 정보를 표시한다.

### 15.5 디바이스 작업

- Given Shutdown 상태의 사용 가능한 디바이스, When 사용자가 Boot를 실행하면, Then 앱은 해당 디바이스를 작업 중으로 표시하고 완료 후 인벤토리를 갱신한다.
- Given Booted 상태의 디바이스, When 사용자가 Open in Simulator를 실행하면, Then Simulator.app에서 해당 디바이스 UI를 표시한다.
- Given Unavailable 상태의 디바이스, When 작업 버튼을 표시할 때, Then 삭제 외 작업은 비활성화한다.
- Given 초기화 또는 삭제 작업, When 사용자가 실행하려고 하면, Then 앱은 실행 전에 확인을 요구한다.
- Given booted 디바이스 삭제 작업, When 사용자가 확인하면, Then 앱은 종료 후 삭제를 수행하고 결과를 표시한다.
- Given 일괄 작업 대상이 여러 디바이스이면, When 작업이 실행될 때, Then 대상별 진행 상태와 성공/실패 결과를 분리해 표시한다.

### 15.6 Target App 설치와 실행

- Given 사용자가 Booted 디바이스와 `.app` 번들을 선택하면, When 설치를 실행할 때, Then 앱은 선택한 디바이스에 Target App을 설치하고 결과를 표시한다.
- Given 사용자가 여러 Booted 디바이스와 `.app` 번들을 선택하면, When 일괄 설치를 실행할 때, Then 앱은 대상별 설치 성공/실패를 표시한다.
- Given 선택한 디바이스가 Booted 상태가 아니면, When Target App 설치/실행 영역을 표시할 때, Then 설치와 실행 동작은 비활성화된다.
- Given Target App이 설치되어 있고 단일 Booted 디바이스가 선택되어 있으면, When 실행을 실행할 때, Then 앱은 bundle identifier를 사용해 Target App을 실행한다.

### 15.7 저장과 제외 범위

- Given 사용자가 창 크기나 분할 위치를 변경하면, When 앱을 다시 실행할 때, Then 마지막 창 크기와 분할 위치를 복원한다.
- Given 사용자가 필터, 디바이스, `.app` 번들을 선택하면, When 앱을 다시 실행할 때, Then 해당 선택값은 복원하지 않는다.
- Given 초기 버전, When 사용자가 제외 범위의 기능을 찾을 때, Then 앱은 해당 기능을 주요 조작으로 제공하지 않는다.

## 16. 초기 제외 범위

초기 버전은 다음 기능을 제공하지 않는다.

- 시뮬레이터 런타임 다운로드, 설치, 삭제
- 로그 스트리밍, 검색, 분석
- `.ipa`, `.xcarchive`, Xcode 프로젝트 빌드 입력
- 여러 Xcode 설치본 동시 스캔 또는 앱 안에서의 Xcode 전환
- 디바이스 페어링 생성, 수정, 해제
- 여러 디바이스 대상 Target App 일괄 실행
- 시스템 알림
- 별도 Preferences 화면
- 주기적 폴링 또는 실시간 이벤트 감지
- CoreSimulator private framework 직접 연동
- Xcode 또는 CoreSimulator 내부 데이터베이스 직접 파싱
- 별도 Device Types 메인 화면
- Xcode 라이선스 동의 같은 권한 상승 작업 실행
- `simctl` 명령 경로 커스터마이징
- 고급 JSON/raw mode
- 자동 새로고침 주기 설정
- 메인 윈도우를 닫은 뒤 메뉴바에서 시뮬레이터를 조작하는 상주 기능
